## 1. 说话的人是谁

一个亲手搭过这类系统、也认真读过社区讨论的产品或解决方案同事，在给正在选型的同行讲清楚情况。

- 先讲读者遇到的问题，后讲工具
- 有判断，但会说明条件；不吹捧，也不贬低
- 讲到能力时，马上说「比如……」
- 不假装中立到没有观点，也不把文章写成广告

## 2. 段落和句子

来自 2026 年 43 篇英文文章的统计：

| 指标 | 数值 | 怎么用 |
|---|---|---|
| 段落长度中位数 | 约 22 词 | 一段 1–3 句。超过 60 词就拆开 |
| 句子平均长度 | 约 16 词 | 长短句交替；长句用来列具体对象，短句用来转折 |
| 单句段落 | 很常见 | 用作转折和强调：`It can get confusing.` `The answer is yes.` |
| 每篇 H2 | 中位数 6 个 | 5–9 个为宜 |
| 每篇列表项 | 中位数 45 条 | 列具体对象、条件、步骤，不列空话 |

中文对应：一段 1–3 句，一般不超过 120 字；多用「比如」「例如」引出具体例子。

## 3. 常用句式

这些句式出现在多篇 2026 年文章里，是这个栏目的「口头禅」。

**它们展示的是句子结构，不是可以照抄的句子。** 测试时发现，AI 会把下面的句子原样搬进新文章（比如「However, a tool that works well at the beginning may not remain suitable for every stage…」）。每篇都这么写，博客很快就会变成模板，读者和搜索引擎都看得出来。用法：
- 学它的结构（先肯定、再转折、再给出具体原因），换成这篇文章自己的对象和细节重写
- 每篇最多借用两三种结构
- 下面的例句不要原样出现在新文章里

**引出问题**
- `If you've worked on <X>, you're probably familiar with this experience: …`
- `Recently, we came across a discussion about <X> on Reddit.`
- `The comments showed that opinions about <X> were mixed.`
- 中文：「最近，我们在 Reddit 上看到一则关于……的讨论。」「从评论区的讨论来看，大家对……的评价并不完全一致。」

**转折，指出真正的问题**
- `But code is not the same as an application.`
- `However, a tool that works well at the beginning may not remain suitable for every stage of a team's development.`
- `Coding is the easy part; everything behind it is harder.`
- `AI can build the basic framework of a CRM very quickly, but there is still a gap between that and a system that is truly ready for enterprise use.`
- 中文：「不过，一款工具在初期好用，并不代表它始终适合团队之后的每个阶段。」「代码不等于应用。」

**给出思路**
- `Today, however, there is another approach.`
- `A clearer way to think about it is this: stop asking …. Instead, ask what problem it helps you solve.`
- `In this guide, we will show how …`

**定位一个产品**
- `<X> is a <category> for <who/what>. It is more like a <直观类比>.`
- `It is better understood as …`
- `Its focus is not only …. It also …`
- 中文：「X 是一个面向……的……。它更像是一个……」

**举例**
- `For example, one customer can have multiple projects, while each project can be linked to contracts, tasks, invoices, and payment records.`
- `Sales teams can view customers, contacts, and opportunities; project managers can view projects, tasks, and delivery progress; finance teams can view contracts, invoices, and payments.`

**有条件地推荐**
- `<X> is better suited to teams that …`
- `If your goal is to build …, you can look at NocoBase first.`
- `If the current goal is simply to …, then Airtable or Feishu Bitable would usually be a better starting point.`
- 中文：「如果你的目标是……，可以先看看 NocoBase。」「……更适合……的团队。」

**收尾**
- `Vibe Coding has significantly lowered the barrier to taking an application from zero to one.`
- `Back to the question at the beginning: …`
- `We hope this article helps you …. Feel free to share it with …`

## 4. 怎么写竞品

- 每个竞品都按同样的结构写，信息密度和 NocoBase 接近，至少写清它是什么、适合谁、有什么 AI 能力
- 先说它擅长什么，再说差异；局限写成「需要确认的地方」：`teams that rely heavily on … should still confirm whether …`
- 不写「但是它不如 NocoBase」。差异用事实说明：数据从哪里开始建、权限粒度、是否可以自托管、计费方式
- 推荐时按读者情况分流，必要时推荐别人：`If the current goal is simply to organize data online…, Airtable or Feishu Bitable would usually be a better starting point.` 这样的段落反而让读者更相信我们对 NocoBase 的推荐

## 5. 不用的词，以及用什么代替

2024 年的文章里这些词每千词出现 6 次以上，2026 年几乎消失，读者一看就觉得是 AI 写的。

| 不用 | 换成 |
|---|---|
| seamless / seamlessly integrates | 说清怎么连接：`connects to MySQL, PostgreSQL and REST APIs as data sources` |
| robust / powerful / comprehensive | 删掉，或写出具体能力：`row-level and field-level permissions` |
| flexible（单独作夸奖） | 写出能改什么：`fields, pages, permissions and workflows can still be adjusted after launch` |
| streamline / boost / enhance efficiency | 写出省掉了哪一步：`administrators no longer update the asset status and history record separately` |
| leverage / harness / utilize | use |
| empower / unlock / elevate / supercharge | 删掉，直接说结果 |
| cutting-edge / game-changer / revolutionize / transformative | 删掉 |
| In today's fast-paced / rapidly evolving landscape | 用具体事件开头（某条讨论、某个产品发布、某个数据） |
| delve into / dive into / deep dive | look at / compare / walk through |
| It's worth noting that / Notably / Importantly | 删掉，直接说 |
| Moreover / Furthermore / Additionally | Also / 直接另起一段 |
| In conclusion / In summary / Overall | 用 `## Conclusion` 小标题，正文直接写结论 |
| Whether you're a startup or an enterprise… | 写清楚具体是谁：`a seven-person department in a 100-person construction company` |
| perfect for / ideal solution | better suited to / a good fit when … |

中文：

| 不用 | 换成 |
|---|---|
| 赋能、助力、打造、加持 | 直接写做了什么：「让销售在客户详情页直接看到最近一次沟通」 |
| 无缝集成、一站式 | 写清连接了什么、在哪里操作 |
| 强大、全面、灵活、高效、轻松 | 删掉，或换成具体能力和具体变化 |
| 降本增效、数字化转型（空用） | 写出省掉的环节、减少的人工步骤 |
| 在当今……的时代、随着……的快速发展（作开头） | 用一条真实讨论或一个具体场景开头 |
| 值得一提的是、总而言之、综上所述 | 删掉 |
| 痛点、抓手、闭环（堆砌） | 说清是什么问题、靠什么解决 |
| 您 | 你（栏目统一用「你」） |

## 6. 标点、格式与 emoji

- 英文破折号（—）少用，每千词不超过 1 个；用逗号、冒号或句号代替。不要用破折号制造「戏剧性停顿」
- 感叹号几乎不用（全栏目 147 篇只有 91 个）
- 列表项可以用分号结尾（`Sales teams can view …;`），这是栏目里常见的写法
- 流程用箭头单独成行：`Lead → Company account → Opportunity → Quotation → Closed deal`
- 链接块每项单独一行：`Website: …`、`GitHub: …`、`GitHub Stars: 22.7k`
- emoji 只做功能标记，各有固定用途：
  - 💬 栏目说明（每篇一次）
  - 💡 延伸阅读 `💡 Read more: [标题](链接)`
  - 🎉 产品公告（blockquote）
  - 🚀 在线体验 Demo
  - 🔎 相关资源
  - ⭐ / ❤️ 文末分享句
  - 对比表里可以用 ✅ ❌ ⭐⭐⭐
  - 正文句子里不加 emoji

## 7. 改写对照

**例 1：产品介绍**

原文（2024，Retool 替代品）：
> Refine is particularly well-suited for developers and teams familiar with the React tech stack who need to build complex, data-intensive applications. It offers seamless integration with React, a powerful component library, and highly flexible customization capabilities, enabling companies to quickly develop highly complex applications with real-time data processing capabilities.

改写（2026 写法）：
> Refine is a React framework for building admin panels, dashboards, and internal tools. It is more like a set of building blocks than a finished platform: data providers connect to REST, GraphQL, or Supabase, and the UI is written in React with the component library your team already uses.
>
> It is better suited to teams with React developers who want full control over the code. Teams that expect business users to adjust pages and workflows themselves will need to plan for that work separately.

改了什么：删掉 seamless、powerful、highly flexible；用「更像一套积木」给出直观定位；写清连接什么、谁来改；最后一句诚实说明不适合谁。

**例 2：开头**

原文（2024）：
> In today's rapidly evolving technological landscape, businesses face escalating challenges. Traditional application development methods often fall short of meeting the fast-paced market demands due to their complex processes and lengthy development cycles.

改写（2026 年《How to Build a Production-Ready IT Operations System with AI and NocoBase》的真实开头）：
> A recent post in Reddit's r/sysadmin described how one user built an ITSM system with AI over a weekend, covering both ticketing and asset management. In actual use, they found it more convenient than many products they had used before.
>
> The comments also raised a different view: AI can quickly generate a Help Desk that looks mature, but that does not mean it already has the data structure, permissions, security, and extensibility required for production use.

改了什么：用一个真实、具体、有正反两面的事件代替空泛的时代背景，读者马上知道这篇文章要解决什么问题。帖子、观点和链接都必须来自真实来源，不能为了故事效果添加细节。

**例 3：讲价值**

原文（2024）：
> Salesforce, as the leading name in the CRM market, is widely adopted by medium and large enterprises for its robust SaaS platform and comprehensive features. However, its powerful capabilities come with a steep price.

改写：
> Salesforce is the CRM many sales teams compare everything else against. Its Enterprise edition costs $165 per user per month, so a 10-person team pays $19,800 in the first year before any implementation work.

改了什么：去掉三个空洞形容词；直接用公开价格算出读者关心的数字。

**例 4：中文**

原文：
> NocoBase 是一款功能强大、灵活高效的无代码平台，能够无缝集成各类数据源，助力企业轻松打造一站式数字化管理系统，实现降本增效。

改写：
> NocoBase 是一个开源的 AI 无代码平台，常用来搭建 CRM、工单、审批这类企业内部系统。比如，团队可以先建好客户、项目、合同、发票几张关联的数据表，再给销售、财务和管理层分别配置不同的页面和权限。业务变了，字段、页面和工作流都可以在界面里继续调整。

## 8. 中英文两版

官网博客的每篇文章都有中英文两版，结构完全一致，但不是逐句翻译：

- **标题各自本地化**：`How to Choose a Smartsheet Alternative: 7 Tools Compared` → 「7 款 Smartsheet 替代品：适合项目管理与业务流程的工具」
- 小标题使用对应的中文固定说法（「产品信息」「X 是什么？」「为什么可以作为 X 替代品？」「与 X 的核心差异」「适合哪些团队？」「简介」「核心特点」「适合场景」「引言」「背景」「相关阅读」）
- 产品名、功能名保留英文（AI Employees 中文写「AI 员工」），中文和英文、数字之间加空格
- 链接换成中文版地址：官网 `https://www.nocobase.com/zh-CN/…`，博客 `https://www.nocobase.com/zh-CN/blog/<slug>/`
- 💬 栏目说明使用中文版（见 `nocobase-facts.md`）
- 中文 description 控制在 60–80 个汉字
